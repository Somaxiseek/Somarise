# Somarise 上线手册

> 写给：你自己一个人，把小程序从「体验版」推到「正式上线」。
> 以 2026-10 的微信规则为准；具体页面文案微信会微调，以小程序后台实际显示为准。

---

## 0. 先回答你最关心的两个问题

**Q：不买云空间，能发布吗？**

**能。发布本身不花一分钱。** 微信不对「上线」收费，不对小程序本体收费，也不强制你买服务器。

但有个前提必须说清楚：**发布 ≠ 能用**。你现在的版本，数据全在后端（体重、饮水、打卡、圈子都在 SQLite / 云函数里），所以别人的手机要能读到自己的数据，就必须有一个「跑着的后端」。花钱的不是发布，是那个后端。

而「免费后端」这条路基本是封的：

| 免费方案 | 现实情况 |
|---|---|
| 微信云开发「免费环境」 | **小程序一旦发布，免费环境的到期时间会被改成「上线后第 15 天」**，之后必须转付费（19.9 元/月）。这是官方文档写死的规则，不是传言 |
| 云开发免费体验活动 | 活动截止 2026-12-31，且仅限控制台创建的体验环境，续期 6 个月一次 |
| 白嫖海外托管（Vercel / Cloudflare） | 走不通。小程序的 request 域名必须**已 ICP 备案**，海外域名备不了案，填不进白名单 |
| 一台自己的电脑长期开着 | 走不通。局域网 IP 不能作为正式环境的请求地址，审核也过不了 |

**结论**：要么每月 19.9 元（云开发），要么每年一两百（自己的服务器 + 备案域名），要么**先发一个「纯本地版」——数据只存在用户手机里，永久零成本**。

**Q：那我到底该怎么选？**

先看第 3 节的三条路线对比，再看第 5 节我给你的建议。

## 1. 你现在卡在哪：体验版 ≠ 上线

| 版本 | 谁能打开 | 怎么进 | 是否需要审核 |
|---|---|---|---|
| 开发版 | 只有你自己（开发者工具 / 真机调试） | 工具里点「预览」 | 否 |
| 体验版 | 你 + 你逐个添加的**体验成员**微信号，名额只有几十人 | 后台生成体验版二维码，扫码进入 | 否（但要先上传代码） |
| **正式版** | 所有人，可被搜索、可分享、可扫码 | 后台「提交审核」→ 审核通过 → 点「发布」 | **是** |

你之前给用户的是**体验版**：手动加人、扫码、几十人上限、随时可能被收回。正式版才是「发出去谁都能用」。

从体验版到正式版，中间隔着三件硬事：**类目 → 备案 → 提审**。体验版不需要这三样，所以你现在还没碰到它们。

## 2. 上线的真实步骤（按顺序做，别跳）

### Step 0｜主体：个人 还是 个体户/公司（**这是最先要定的**）

这一步定错，后面全要返工。

| | 个人主体 | 企业/个体工商户 |
|---|---|---|
| 注册成本 | 0 | 营业执照（个体户几百元可办）+ 认证 300 元/年（或对公打款验证） |
| 可选类目 | 窄：工具类（含**健康管理**）、体育-在线健身、生活服务（部分） | 宽 |
| 微信支付 | **不能开通** | 可以 |
| 社交 / UGC（评论、动态、点赞、圈子） | **高风险，大概率驳回** | 可以（部分需额外报备） |
| 微信运动步数 API | **不能用** | 可用（需授权） |
| 广告 / 流量主 | 不能 | 可以 |

你现在的小程序是**个人主体**（我按你有体验版、没提过营业执照推断，若不是请告诉我）。

**个人的红线里，最要命的一条是「社交 / UGC」**。你的圈子页有：小组、动态流、点赞。这在审核眼里就是 UGC 社交，个人主体是重灾区。这不是「可能碰运气」，是类目表里明确不开放的方向。

### Step 1｜基本信息 + 服务类目

后台：`设置 → 基本设置`

- **名称**：别用「中国」「官方」「全国」；别和已有小程序重名。个人主体一年只能改 2 次名，起之前想清楚
- **头像 / 简介**：简介要具体，写「记录体重腰围、饮水量与运动时长，生成个人变化回顾」，不要写「一站式健康管理平台」这种空话
- **服务类目**：二选一
  - **工具 → 健康管理**（推荐，适用「身高、体重等健康数据记录」）
  - **体育 → 在线健身**（适用「健身运动的在线学习/指导」）

类目必须和实际功能对得上。审核会拿你的功能和类目逐条比对，对不上直接驳回。

### Step 2｜小程序备案（工信部，绕不过）

后台：`设置 → 基本设置 → 小程序备案`

2023 年 9 月起，**所有小程序上线前必须完成备案**，没备案不能发布。

- 个人主体可以备案，用身份证 + 手机号 + 人脸核验
- 流程：填资料 → 平台初审（1–2 天）→ 工信部短信核验 → 通信管理局终审（**1–20 个工作日，通常 3–7 天**）
- 备案主体必须和小程序认证主体一致
- 备案期间可以继续开发、提测，只是不能发布

**这是整个流程里唯一你没法加速的环节，越早提交越好。**

### Step 3｜后端（见第 3 节，三条路选一条）

### Step 4｜合规配置（最容易被忽略，但会卡审核）

- **《小程序用户隐私保护指引》**：后台 `设置 → 服务内容声明 → 用户隐私保护指引`。必须逐项声明你收集什么：
  - 昵称、头像（用户主动填写）
  - **身高、体重、腰围、饮水量、运动记录** ← 这些属于**敏感个人信息**，要写清用途、存储方式、能否删除
  - 不填这个，相关接口会被微信直接拦截
- **用户协议 / 隐私政策页面**：小程序里要能点开。审核员会找
- **健康措辞**：全站不能出现「诊断」「治疗」「医学建议」「改善XX疾病」。你现在的「健康提示」文案要审一遍，写成「参考建议」而不是「医嘱」

### Step 5｜上传 → 提审 → 发布

1. **先跑一遍自检**：`npm run preflight`。它会把「云端跑不起来 / 会卡审核 / 包里混进测试残留」的问题一次列出来，有 ✗ 就说明还不能传（`npm run preflight` 只读，不改文件）。检查项：云环境 ID、`social` 开关、云函数包与源码是否一致、主包体积（2MB 上限）、测试残留、个人主体禁用的能力、医疗措辞、页面文件是否齐全、Somaxis 接口是否仍关闭
2. 开发者工具「上传」，填版本号 + 项目备注
3. 后台 `版本管理 → 开发版本 → 提交审核`
4. **填写测试账号**：如果审核员打不开就看不到功能，会被判「功能不完整」驳回。你现在走云开发的话，审核员进来就是新用户，得保证**空数据状态下页面不白屏、有引导**
5. 审核 1–7 个工作日（实际多数 1–2 天）
6. 通过后点「发布」，可选**灰度发布**（先放 10% 用户）再全量

### Step 6｜上线后

- 数据看板：`统计`（访问、留存、页面路径）
- 每次改动都要重新提审（改文案、改样式一般也要），所以**首版别把没做完的功能放进去**
- 记得在小程序里公示备案号

## 3. 三条后端路线，摊开算

### 路线 A：微信云开发（最省事，推荐给你）

| 项 | 数值 |
|---|---|
| 域名 | **不需要**。`wx.cloud.callFunction` 走微信内部通道，不受 request 白名单限制，也不需要域名备案 |
| 服务器 | 不需要 |
| 费用 | 发布后免费环境只有 15 天 → 之后 **19.9 元/月（约 239 元/年）** |
| 配额 | 20 万次调用 / 2GB 存储 / 5GB CDN 流量，你这个体量几年都用不完 |
| 改造量 | **几乎为零**。你的 `cloudfunctions/somactiveApi` 已经写好了，只要建环境、填 `cloudEnv`、上传云函数 |
| 上线速度 | 最快，当天就能提审 |

**代价**：每月固定 19.9。用户 0 人的时候也在扣。

### 路线 B：自己的服务器 + 备案域名（长期更便宜，但要动手）

| 项 | 数值 |
|---|---|
| 服务器 | 轻量应用服务器，新用户/学生优惠约 99–300 元/年，续费会涨 |
| 域名 | 30–80 元/年（.com / .cn） |
| ICP 备案 | 免费，但**7–20 个工作日**，且要提交身份证、拍照核验 |
| HTTPS 证书 | 免费（Let's Encrypt / 云厂商免费证书） |
| 改造量 | 中等：把现有 `server/http.js` 部署上去 + Nginx 反代 + 改 `runtime.apiBase` 为 `https://api.xxx.com` + 后台配 request 合法域名 |
| 运维 | 你要自己管：进程守护、备份、续费、证书到期 |

**代价**：首年看着便宜（约 150–400），但续费、运维、备案的时间成本都是你的。**个人备案的域名用途要写得和实际相符**，否则管局会打回。

### 路线 C：纯本地版（永久 0 元，但要改代码）

| 项 | 数值 |
|---|---|
| 费用 | **0**，永久 |
| 需要后端 | 不需要。数据全部存手机本地（`wx.setStorage` / 本地文件） |
| 能得到 | 记录、圆环、本周进度、月度回顾、分享图、体重曲线——**全部单机可跑** |
| 会失去 | 圈子、今日榜、跨设备同步、换手机不丢数据 |
| 改造量 | **大**：现在所有读写都走 `api()`，要加一层本地存储适配器（约等于写一个 mini 数据库） |
| 审核 | 最容易过。没有 UGC、没有服务器、没有备案域名，个人主体最舒服的状态 |

**注意**：路线 C 的「换手机就没了」是真实的用户痛点。可以折中：本地存主数据 + 允许导出/导入（生成一个文件发给自己）。

## 5. 我给你的建议

**先不要急着上线，先做一件事：把「圈子」从首发版本里拿掉。**

理由不是技术，是两层：

1. **合规**：个人主体 + UGC 社交 = 高驳回率。你辛苦做完的圈子，可能正是让整个小程序卡在审核的那一项
2. **产品**：你自己刚说的——「不想做成让人自律的工具，排行榜不是最重要的」。那首发版本本来就不该有榜。这反而是个顺势的决定

具体路线：

```
① 首发：路线 C（纯本地）或 A（云开发），只保留「记录 + 自己的变化 + 分享图」
   ├─ 个人主体、类目「工具-健康管理」、无 UGC → 审核最顺
   └─ 圈子、排行、点赞用代码开关关掉，代码留着
② 备案同步提交（Step 2），别等
③ 首发上线、拿真实用户反馈
④ 真有几十个人在用、真的想要「互相看见」时，再决定：
   ├─ 开云开发付费（19.9/月）+ 圈子灰度放开
   └─ 或者升级成个体户主体，把社交类目正经做
```

**为什么先 C 不先 A？** 因为你现在的产品哲学是「想记就记，没有负担」。一个纯本地的工具，天然就是「没有负担」的：不用登录、不用联网、不会因为别人看到而记。而且它 0 成本，你可以慢慢做一年。

**但 C 有真实代价**：我得给你写本地存储层，工作量不小（估计要把所有 `api()` 调用点都包一层），而且换手机数据会丢。如果你更想快点上线看反应，那就 A —— 花 19.9/月买一个「立刻能上、数据不丢、以后能加圈子」的位置，我觉得这笔钱值。

**一句话**：想快 → A，想省 → C，别选 B（省不了多少钱，还要背上运维和域名备案）。

## 6. 提交审核时怎么填（降低驳回率的实操）

**版本描述**（给审核员看的）：
```
本版本提供个人健康数据记录：体重/腰围、每日饮水量、运动时长。
用户可查看自己的周/月变化曲线与回顾。所有数据仅用户本人可见。
不含社交、不含医疗建议、不含交易。
测试路径：首页 → 右下滑块进入记录 → 选择「有氧」→ 填时长 → 保存。
```

**最容易驳回的 8 个原因**（对照自查）：

1. 类目和功能不匹配（选了工具，却做了社区）
2. 空数据白屏 / 审核员看不到功能
3. 有 UGC 但没内容安全审核能力（个人主体尤其）
4. 出现医疗、诊断、疗效表述
5. 隐私指引没声明就调了用户信息接口
6. 诱导分享（「分享得积分」「分享解锁」）— 微信明令禁止
7. 名称/头像侵权或含敏感词
8. 有未完成的死链、按钮点了没反应

你现在的代码里第 6 条要特别注意：分享必须**纯自愿、无奖励**。

## 附二：单词读音放哪（词库涨到 6000–8000 词之前必须处理）

测试期 100 个词，读音是小 m4a，跟着小程序包走（`miniprogram/audio/`，26kbps 单声道，一个词约 6.5KB），
由 `npm run audio` 用 macOS 的 `say` + `afconvert` 生成，不依赖任何在线 TTS，也不占数据库。

**为什么不占数据库**：音频不进 SQLite、不进云数据库，它是静态文件；数据库里只有你的复习进度（一个词一条记录，几十字节）。

**什么时候必须搬走**：

| 词量 | 音频合计 | 放哪 |
|---|---|---|
| 100 词（现在） | 0.6 MB | 可以跟着主包走 |
| 1000 词 | 6.5 MB | 已经超主包 2MB 上限，必须搬 |
| 6000 词 | 39 MB | 云存储 / CDN |
| 8000 词 | 52 MB | 云存储 / CDN |

云开发（或对象存储）的存储额度是 GB 级，50MB 大概占 1%，**真正要留意的是流量不是空间**：
一次播放 6.5KB，5GB/月的 CDN 流量约等于播放 80 万次。个人用完全够。

**搬家步骤（三步）**

1. `node scripts/build-audio.js --out dist/audio`（补全所有词，输出到 `dist/audio`）
2. 把 `dist/audio` 整个目录传到云开发「存储」的 `Somarise/audio/` 下，拿到访问前缀
3. 改 `miniprogram/config/audio.js` 里的 `AUDIO_BASE='https://<你的环境>.tcb.qcloud.la/Somarise/audio/'`
   （末尾带斜杠），前端只走这个常量，别处不用动

搬完记得把小包里的 `miniprogram/audio/` 删掉，否则白白占 2MB 主包额度。

## 6. 体验版最快路径（手机不连同一个 Wi-Fi 也能用）

**先说结论**：手机要和电脑脱离，只有一条路走通——**云开发（路线 A）**。

为什么局域网 IP 和「内网穿透」都不行：真机（含体验版）走的是 `wx.request`，**请求域名必须是已备案域名并填进小程序后台白名单**；`192.168.x.x`、`xxx.ngrok.io`、`xxx.trycloudflare.com` 都填不进去。`wx.cloud.callFunction` 走微信内部通道，不受这条限制，所以它能在任何网络下用。

### 几个必须知道的行为

- **`cloudEnv` 一填，开发者工具也走云**（不再读本机 8787）。这是故意的：你看到的就是手机看到的那一套。回到本机快速调试：`node scripts/cloud-env.js off`。
- **两套数据不互通**：云上是一份新库，从零开始（新用户就是空数据，正好用来验证「空数据不白屏」）。本机 8787 的演示数据留在本地。
- **集合名 `Somarise_trial_data`**：云函数第一次被调用时自己建；万一环境权限不给建，去「云开发 → 数据库 → 新建集合」手填这个名字即可。
- **音频**：词库音频现在跟着主包走（0.6MB），够用；扩到上千词再按第 5 节搬到云存储。
- **上传前 preflight 会拦**：`cloudEnv` 为空时 `npm run upload` 直接退出，避免传上去一个「手机上打不开」的版本。
- **体验版也有 1 个月试用期限制**：免费额度是环境的，不是版本的；到期前在云开发控制台看用量，超了要么升配要么迁。

### 体验版 → 正式版（以后的事）

体验版只解决「你和小范围的人能用」。要公开发布还得走第 2 节的类目 + 备案 + 提审，其中**备案 1–20 个工作日**是最慢的一环，建议现在就去后台把备案提交了，和体验版并行推进。
