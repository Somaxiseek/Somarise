2026-10-27：新增**局域网直连**通道，手机可以先看开发版/体验版而不必等云环境。手机端在 `app.js` 里分三种模式：`wechat-cloud`（配了 cloudEnv）、`local-lan`（配了 apiBase，真机直连本机）、`local-demo`（开发者工具模拟器，走 127.0.0.1）。后端 Host 白名单放行 RFC1918 私有网段，公网 Host 仍 403；默认监听地址仍是 `127.0.0.1`，只有 `npm run start:lan` 才监听 `0.0.0.0`。

## 方案 A：局域网直连（先看效果用这个）

前置：手机与电脑连同一个 Wi-Fi（手机开热点、电脑连该热点也算）。

1. 电脑上执行 `npm run lan`，脚本会把当前局域网 IP 写进 `miniprogram/config/runtime.js` 的 `apiBase`，并打印地址。
2. 另一个终端执行 `npm run start:lan`，后端监听 `0.0.0.0:8787`，终端会列出手机可访问的地址。
3. 微信开发者工具里点「编译」，再点「预览」，用微信扫码。
4. 手机进入小程序后，点右上角「…」→「开发调试」→ 打开调试，然后**退出重进**。打开调试模式后小程序才跳过合法域名校验，能请求 `http://192.168.x.x:8787`。
5. 首页应直接显示默认项目（跑步 / 力量训练 / 饮水）与体测卡；若还提示未配置，说明 `runtime.js` 没被重新编译，重开一次编译。

限制：电脑关机或换网络就用不了；换 Wi-Fi 后 IP 变了要重跑 `npm run lan`。局域网内其他人也能访问这个演示服务，只在可信网络里用。

## 方案 B：云开发（体验版正路）

手机不依赖电脑，也不需要域名白名单。下面是成本结构、隔离边界与开通步骤。

## 成本与「共用云环境」（2026-10-28 核实官方文档）

**三档成本，按「给多少人用」选，不按功能选：**

| 场景 | 做法 | 花钱 |
|---|---|---|
| 自己一个人、一台设备 | 不做云，数据放本机 storage | 0 |
| 自己用但要多设备同步 | 自己开一个云环境，**不发布上线** | 0 |
| 给 15 人以内试用（个人主体） | 上传代码设成**体验版**，把对方加为体验成员 | 0 |
| 给更多人用 / 要能被搜到 | 必须**发布上线** | 上线后第 15 天起 19.9 元/月（基础套餐，40,000 资源点/月） |

依据：
- 免费环境：每个「没有云环境」的小程序账号可创建一个，**未发布上线阶段无需续费**；发布上线后环境到期时间变为**上线后第 15 天**，需转付费。活动截止 2026-12-31（已开通的照旧）。
- 体验版不算「发布上线」：线上版本要走「提交审核 → 发布」。体验版没有过期时间，但**只有体验成员能打开**。
- 体验成员上限（个人主体）：**15 人**（项目成员也是 15）；非个人未发布 30，已认证/已发布 60~90。
- 体验版的坑：真机预览二维码十几分钟过期，体验版二维码约 7 天；重新上传代码后要**重新设置体验版**才生效。

**为什么不做「环境共享」（Somaxis 蹭 Somarise 或反过来）：**

1. **省不到钱**：共享的真实收益只有「被共享方不必自己买套餐」。而免费环境在未上线阶段本来就是 0 元，Somaxis 自己用不上线 → 独立环境一样 0 元。
2. **硬前提是同主体**：只能授权给**同主体**下的小程序/公众号；两个小程序主体不同就根本共享不了。
3. **身份字段会变**：跨账号调用时，资源方云函数里 `getWXContext()` 的 `APPID/OPENID` 是**资源方**侧的，来源方身份在 `FROM_APPID / FROM_OPENID / FROM_UNIONID`。我们的 `server/mobile-gateway.js` 只读 `APPID`（写死 `wx6b81913a5a90b3e0`）+ `OPENID`，一旦被别的小程序调用会直接 401；而且用户若从未进过资源方小程序，资源方侧可能没有对应身份。
4. **共享还要多一个函数**：资源方必须有 `cloudbase_auth` 云函数做鉴权，调用方 `cloud.init()` 时先执行它，否则报找不到 FunctionName。
5. **生命周期绑定**：Somarise 是给不同人用的产品，会频繁改数据结构、可能重置环境、将来可能迁移；Somaxis 的私人数据挂在上面等于绑死在别人的发版节奏上。
6. **越权面**：共享环境里的云函数是 admin 权限，能读写该环境所有集合。两套业务塞一个函数，「只碰自己集合」就只剩代码自律，不再有权限边界。账单和配额也混算。

结论：**两个产品各自开自己的免费环境，互不共享。**只有一种情况才考虑共享：Somarise 已付费、Somaxis 又确实不想自己开环境 —— 但那时共享也只是省 0 元，所以实际上没有共享的理由。

## 隔离边界

- 仅 Somarise AppID `wx6b81913a5a90b3e0`；不使用 Somaxis 云环境或会员数据库。
- 手机使用 `wx.cloud.callFunction`，服务端只信任 `getWXContext()` 的 APPID/OPENID，忽略请求中伪造的身份。无需 AppSecret。
- 新用户独立建档，不导入本地演示用户。云端 Somaxis 绑定关闭；本地演示码不能用于云端。
- 数据库仅云函数可访问：集合客户端读取与写入权限均设为禁止（安全规则 read:false / write:false）。不要公开集合。
- OCR 仍是模拟识别；图片只在函数内存处理，不上传云存储。饮食和正式词本未接入。

## 开通与部署

1. 在微信开发者工具中确认打开本项目和上面的 Somarise AppID，打开「云开发」。若未开通，创建独立测试环境，例如 Somarise-trial。遇到付费、自动续费、协议或授权变更先由账号所有人确认，不能借用 Somaxis 环境。
2. 取得环境 ID（不是 AppSecret），确认环境所属/关联 AppID 正确。
3. 在数据库创建 `Somarise_trial_data` 集合，并将客户端读写均设为禁止。不要导入任何真实会员或旧演示数据库。
4. 把环境 ID 填入 `miniprogram/config/runtime.js` 的 cloudEnv。cloudFunction 保持 somactiveApi。
5. 执行 `npm run build:cloud`，刷新开发者工具；为 cloudfunctions 目录选择独立测试环境。
6. 右键 somactiveApi，选择上传并部署、云端安装依赖。函数入口 index.main，运行时 Node.js 18 或以上；SDK 已固定3.0.1。禁止上传 `.local`、测试数据和 Somaxis 代码；云函数目录已仅包含所需业务代码。
7. 重新编译，点击预览，用管理员微信扫码。可预览不等于已正式发布，也不等于已通过真机验收。
8. 如需成员持续体验，先在小程序后台添加体验成员，再上传并设为体验版；涉及微信后台必要声明/权限时由账号所有人确认。此流程不提交正式审核或发布。

## 真机验收清单

- 管理员扫码后显示自己的空白独立账号及默认任务，无演示记录；昵称可修改。
- 创建项目、手动打卡、退出重新进入仍有记录。
- 饮水记录300ml，再记录200ml显示500ml；纠正总量后重新进入正确；冲突不会静默覆盖。
- 两个微信账号记录隔离；小组默认不分享，明确授权后才展示允许的运动信息，退出后拒绝访问。
- 模拟截图必须确认才保存；重复提交不新增重复记录。
- 无 Somaxis 正式绑定、无真实会员数据访问，英文学习等待词本。

## 当前容量与后续工作

体验版每个用户一份事务快照，另有小组元数据文档；单文档业务限制700KB，小组读取最多50人。适合小范围体验，长期扩展前必须改为分页的逐条记录、分组索引与限流，不能把它当作最终生产数据库设计。云端依赖安装、真实微信身份、数据库事务SDK及手机兼容性仍必须部署后验证。
